# Portfolio Build Write-Up

## What I Built

I built a personal portfolio to present my software development, machine learning, and project work as clear evidence of what I can build.

Instead of using the portfolio only as an online resume, I structured it around real projects, technical skills, experience, and case studies so that visitors can explore the work behind my claims.

## Stack I Chose

I built the portfolio using:

- HTML
- CSS
- JavaScript
- Git and GitHub
- GitHub Pages

I chose this stack because it is lightweight, free to host, easy to understand, and easy to maintain.

For my current portfolio, I did not need a backend or a large frontend framework. A static website was enough to present my projects, case studies, links, and technical experience while keeping deployment simple.

## How AI Helped

AI was used as a development and thinking assistant throughout the project.

It helped me:

- plan the portfolio structure,
- improve page and case-study organization,
- review and debug code,
- improve technical explanations,
- think through design and usability decisions,
- and turn project work into clearer portfolio evidence.

I still reviewed the generated suggestions, tested the implementation, made the final decisions, and changed outputs when they did not fit the project.

## Hardest Thing That Broke

One of the harder parts was turning separate technical projects into a consistent portfolio rather than simply listing project names.

I had to make sure the navigation, project presentation, GitHub links, deployed pages, and case-study structure worked together.

My FlyRank ML capstone also gave me an important example of why technical results need careful validation. The Random Forest measured approximately 63.2% accuracy under a random split, but approximately 58.4% under client-grouped validation.

Instead of presenting only the higher result, I used the more demanding validation result to communicate the limitations of the model more honestly.

## What I Learned

The main lesson from building the portfolio was that shipping the technical work is only part of the process.

A useful portfolio also needs to explain:

- what problem I solved,
- what I personally did,
- what result I obtained,
- what limitations remain,
- and where AI contributed.

I also learned that AI output needs human review rather than being accepted automatically.

## What I Will Build Next

My next portfolio case study will be my **Face Recognition Attendance System**.

The case study will cover:

- the attendance problem,

- real-time computer-vision processing,
- liveness detection,

- results,
- limitations,

I will use the same **Problem → What I Did → What Came of It** structure so that future projects remain consistent with the rest of my portfolio.
