# Next Case Study Plan

## Where My Next Case Study Will Go

My next case study will be added to the **Projects / Case Studies** section of my portfolio.

Each case study will have its own clear project presentation so that recruiters, mentors, and other visitors can quickly understand the problem, my contribution, the result, and what I learned.

---

## How I Will Add My Next Case Study

I will reuse the same three-beat structure for future portfolio case studies:

### 1. Problem

I will explain:

- What problem I was trying to solve.
- Who experiences the problem.
- Why the problem matters.
- What I wanted the project to achieve.

### 2. What I Did

I will explain:

- My approach to solving the problem.
- The technologies and tools I used.
- The important implementation steps.
- The technical decisions I made.
- Any challenges I encountered and how I handled them.

### 3. What Came of It

I will show:

- The final result.
- Screenshots or architecture diagrams.
- The GitHub repository.
- A live demo, when available.
- Important results or observations.
- Current limitations.
- What I learned from building the project.

---

## Process for Publishing a New Case Study

For each future project, I will:

1. Finish and test the project.
2. Clean and document the GitHub repository.
3. Collect useful screenshots, diagrams, and results.
4. Write the case study using **Problem → What I Did → What Came of It**.
5. Add the GitHub repository link.
6. Add a live demo link when one is available.
7. Add the case study to the Projects / Case Studies section of my portfolio.
8. Check that the page works correctly on desktop and mobile.
9. Review the content for clarity, accuracy, and privacy.
10. Publish the updated portfolio.

The case study will explain the problem of manual attendance management and how I approached it using computer vision.

It will cover:

- Face registration and recognition.
- Real-time webcam processing.
- Face embeddings and classification.
- Liveness checks using eye blinking and head movement.
- Attendance recording.
- The application interface.
- System workflow and architecture.
- Results and screenshots.
- Current limitations.
- Possible future improvements.

The purpose of the case study will be to show not only the final application, but also the technical decisions, challenges, results, and lessons from building it.
